# Dungeon2D v0.2.1 - Implementation Specification

## Context
This specification outlines a targeted UI refactoring for the initial connection modal (welcome dialog) in Dungeon2D. The objective is to transition from a static, vertically stacked form to a dynamic, tabbed interface to separate the "Create Room" and "Join Room" workflows, enhancing user experience and clarity.

## Requirements

* **Tabbed Interface:**
  * Implement two horizontally aligned tabs at the top of the welcome dialog: "Create Room" and "Join Room".
* **Dynamic Form Fields:**
  * **Player Handle:** A mandatory text input field that remains visible and active regardless of which tab is selected.
  * **Join Code:** A conditional text input field that is exclusively visible when the "Join Room" tab is active. It must be hidden entirely during the "Create Room" workflow.
* **Dynamic Action Button:**
  * The primary submission button at the bottom of the modal must dynamically update its text and emitted event based on the active tab (i.e., displaying "Create Room" or "Join Room").

## Code Changes & Technical Implementation

* **`index.html` & `style.css`**
  * Restructure the `#ui-layer` connection modal DOM to include a tab navigation container (`<nav>` or flex `<div>`) and a unified form container.
  * Implement CSS Flexbox for the horizontal tab layout. Ensure tabs have distinct active/inactive visual states aligned with the existing minimalist dark-mode theme[cite: 7].
  * Avoid hard-coded pixel widths for the tabs; use fractional or flexible sizing to ensure responsiveness[cite: 6].
  * Utilize CSS utility classes (e.g., `.hidden { display: none; }`) to toggle the visibility of the "Join Code" input container.

* **`src/ui/UIController.js`**
  * **State Management:** Introduce a local state variable (e.g., `activeTab`) to track the current UI mode.
  * **Event Listeners:** Attach `click` event listeners to the tab elements. Upon clicking a tab:
    1. Update the active visual state of the tabs.
    2. Toggle the `.hidden` class on the "Join Code" input container.
    3. Update the `textContent` of the primary action button.
  * **Validation & Submission:** Update the button's `click` event handler to check the `activeTab` state. 
    * If "Create Room", validate only the Player Handle and emit `ui:create_room`.
    * If "Join Room", validate both the Player Handle and the Join Code before emitting `ui:join_room`.

## Constraints & Edge Cases

* **Responsive Design:** The tabbed interface and form elements must remain fully functional and visually intact on narrow viewports down to a 320px width[cite: 6].
* **State Retention:** If a user types a Player Handle while in the "Create Room" tab and then switches to the "Join Room" tab, the entered handle text must persist and not be cleared.
* **Modularity:** Ensure the `UIController.js` updates do not bleed into or modify the core `WebRTCEngine` or `GameLoop` logic[cite: 6].
* **Definition of Done:** Ensure `CHANGELOG.md` is updated to reflect v0.2.1, all newly added UI logic functions have JSDoc comments, and no placeholder comments remain[cite: 6].
