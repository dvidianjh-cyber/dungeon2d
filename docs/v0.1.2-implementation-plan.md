# Goal Description
Implement the Dungeon2D v0.1.2 specification which introduces inter-player collisions and static environment obstacles, expanding the room data structure and enhancing the physics engine.

## Proposed Changes

### 1. `src/game/RoomManager.js` (Data Layer)
- **Obstacles Schema**: Extend the `roomData` object to include an `obstacles` array.
- **Default Obstacles**: Populate the default room with 4 static, square/rectangular obstacles of varying dimensions, spread out across the 1000x1000 area.
  - Example obstacle: `{ x: 200, y: 200, width: 100, height: 100 }`

### 2. `src/game/GameLoop.js` (Physics Engine)
- **AABB Collision Function**: Create a new helper function `checkAABB(rect1, rect2)` to detect intersections between two bounding boxes.
- **Player Hitbox**: Treat the local player as an AABB for collision purposes, with width and height equal to `radius * 2`.
- **Peer Collision**: 
  - Retrieve the most recent peer states from the `RenderEngine` or maintain a cache in `GameLoop` (by listening to `network:peer_state`).
  - To achieve the "sliding" effect, we will test movement on the X and Y axes independently.
  - If moving X causes a collision with a peer's AABB, we cancel the X movement.
  - If moving Y causes a collision with a peer's AABB, we cancel the Y movement.
- **Obstacle Collision**:
  - Apply the exact same independent-axis AABB checking against all objects in `roomManager.getRoomData().obstacles`.

### 3. `src/render/RenderEngine.js` (Visuals)
- **Rendering Obstacles**: 
  - Inside `drawRoom()`, loop through the `obstacles` array from the `RoomManager`.
  - Draw them using `ctx.fillRect()` and `ctx.strokeRect()` with a distinct fill color (e.g., dark gray `#333` with a `#555` border) to contrast against the black grid game space.
- **Peer State Cache**: Ensure `GameLoop` can access the current peer positions. We can expose a `getPeers()` method from `RenderEngine` or have `GameLoop` track them directly via the Event Bus. Tracking them in `GameLoop` is cleaner for decoupling state from rendering.

## Verification Plan
- **Manual Verification**: Run `npm run dev`.
- Start as Host, verify the 4 obstacles are rendered correctly on the grid.
- Move into the obstacles from all 4 directions, verifying that the AABB collision prevents overlap and allows sliding along the edge.
- Connect a Client in a second window. Move the Host and Client into each other.
- Verify that they block each other's movement and slide around each other properly based on asynchronous peer state data.
