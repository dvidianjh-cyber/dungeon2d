# Goal Description
Implement the Dungeon2D v0.1.1 specification which focuses on UX improvements (immediate host entry, persistent UI overlays), player identity management (handles), rendering enhancements (camera zoom), and environment adjustments.

## Proposed Changes

### 1. `index.html` & `style.css` (Persistent UI & Connection Modal)
- **Modal Update**: Add a mandatory text input for "Player Handle" in the connection modal.
- **Header Bar**: Add a top-anchored absolutely positioned `div` containing "Dungeon 2D" and a menu icon placeholder.
- **Status Toolbar**: Add a bottom-anchored absolutely positioned `div` for the host to display the Join Code and connected peer count.
- **Styling**: Use pure CSS Flex/Grid for positioning without hard-coded pixel offsets. Keep responsiveness down to 320px.

### 2. `src/ui/UIController.js` (UI Logic)
- **Handle Validation**: Validate the player handle input before emitting `ui:create_room` or `ui:join_room`, passing the handle as an argument.
- **Persistent UI Management**: Expose methods to show/hide the Header and Status Toolbar, and update the displayed join code and peer count.
- **Host Immediate Entry**: Remove the blocking waiting screen. Ensure the connection modal hides immediately upon room creation.

### 3. `src/main.js` (Wiring)
- Update `ui:create_room` and `ui:join_room` listeners to capture the user's handle and pass it to `webrtcEngine`.
- On `network:ready_host`, immediately hide the connection modal, show the persistent toolbars, and call `gameLoop.start()`.
- Keep track of peer connections to update the peer count in the UI.

### 4. `src/network/WebRTCEngine.js` (Identity & Security)
- **Local Handle**: Store the local user's handle.
- **Initialization Payload**: When a connection opens, send an initial `INIT` payload over the DataChannel containing the user's sanitized handle.
- **Sanitization**: Implement a basic HTML escape function to sanitize incoming string payloads (handles, chat in the future) before dispatching them to the event bus.
- **Peer State**: Append the handle to the local player's state payload (or sync it once on init, but ensure `RenderEngine` has access to it).

### 5. `src/game/GameLoop.js`
- Include the player's handle in the state passed to `RenderEngine` or keep it decoupled and let `RenderEngine` retrieve handles from a central store/event. (Will add handle to player object for simplicity).

### 6. `src/render/RenderEngine.js` (Zoom & Text)
- **Zoom Logic**: Add a `wheel` event listener to adjust a global `zoomScale` variable (e.g., between 0.5 and 3.0). Ensure the listener is a named function.
- **Matrix Transformation**: In `render()`, apply `ctx.scale(this.zoomScale, this.zoomScale)` strictly *after* `ctx.translate()` so the camera remains centered on the player.
- **Text Rendering**: Use `ctx.fillText()` to draw player handles centered beneath their avatars, adapting cleanly to the applied zoom.

### 7. `src/game/RoomManager.js`
- Adjust the default room bounds from `2000x2000` to `1000x1000`.

## Verification Plan
- **Manual Verification**: Run `npm run dev`.
- Start as Host: Enter handle, verify immediate transition to canvas with Header and Status Bar (showing Join Code and 0 peers). Use mouse wheel to verify zoom functionality.
- Start as Client: In a second window, enter handle and Join Code. Verify both windows show each other's avatars with the correct sanitized handles beneath them.
- Verify that moving respects the new 1000x1000 boundary.
- Test viewport responsiveness down to 320px width.
