# Implementation Plan - Dungeon2D v0.2.1

Refactor the welcome connection dialog from a static, vertically stacked modal into a responsive, tabbed interface separating the "Create Room" and "Join Room" workflows.

## User Review Required

> [!IMPORTANT]
> **Key Architecture Decisions:**
> 1. **Unified Form Architecture:** A single primary action button (`#btn-submit-action`) dynamically updates text and dispatch target based on `activeTab` ('create' | 'join').
> 2. **State Retention:** The Player Handle input is shared across tabs, persisting user input seamlessly when switching between "Create Room" and "Join Room".
> 3. **Clean Decoupling:** All UI changes are confined to `index.html`, `style.css`, and `UIController.js`. Core networking (`WebRTCEngine`) and game loop logic remain untouched.

  - Smooth hover and transition effects.
  - Responsive down to 320px viewport width.

### Core UI Controller

#### [MODIFY] [src/ui/UIController.js](file:///c:/Users/dvidi/Documents/Progamming/dungeon2d/src/ui/UIController.js)
- Introduce state variable `this.activeTab = 'create'`.

- Implement `setActiveTab(tabName)`:
  - Toggles `.active` classes on tab buttons.
  - Shows/hides `#group-join-code` using `.hidden`.

- Implement unified submit handler:
  - Validates player handle for both tabs.
  - If on "Create Room" tab, emits `ui:create_room`.
  - If on "Join Room" tab, validates join code and emits `ui:join_room`.
