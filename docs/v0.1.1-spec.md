# Dungeon2D v0.1.1 - Implementation Specification

## Context
This specification outlines the technical requirements for upgrading the Dungeon2D engine to version 0.1.1. It builds upon the scaffolding established in v0.1.0-walkthrough.md. The focus is on improving UX with persistent UI overlays, adding player identities, introducing camera scaling, and tweaking world parameters. All updates must adhere to the modular ES6 architecture and strict quality guardrails defined in initial-spec-and-instructions.md.

## Requirements

* **Immediate Host Entry:** The host must transition immediately to the active game canvas upon creating a room, without waiting in a lobby for peers to connect.
* **Persistent UI Overlays:** 
  * **Header Bar:** A top-anchored bar displaying the title "Dungeon 2D" and a placeholder menu icon.
  * **Status Toolbar:** A bottom-anchored bar for the host displaying the active Join Code and the current number of connected peers.
* **Player Identities (Handles):**
  * The initial connection modal must require a string input for a player handle before allowing room creation or joining.
  * Handles must be rendered on the Canvas directly beneath the corresponding player's face avatar on all connected instances.
* **Camera Zoom:** The mouse wheel must smoothly scale (zoom in/out) the rendered grid and entities.
* **Room Scale Adjustment:** The default room bounds must be reduced by 50%.

## Technical Implementation Details

* **`src/ui/UIController.js`**
  * Add a required text input field for the user handle to the dark-mode connection modal.
  * Implement the new Header and Status Toolbars as absolutely positioned HTML overlays over the Canvas using pure CSS flex/grid layouts. 
  * Do not use hard-coded pixel offsets for these new UI elements.

* **`src/network/WebRTCEngine.js`**
  * Append the user's handle to the strict JSON initialization payload sent over the DataChannels.
  * Sanitize all incoming WebRTC string payloads (including the new handle) before storing or rendering them to prevent XSS vulnerabilities.

* **`src/engine/RenderEngine.js`**
  * **Zoom Logic:** Attach a `wheel` event listener to manage a global `zoomScale` variable. The Canvas transformation matrix must apply this scale strictly *after* calculating the fixed-center camera translation to ensure the local player remains centered. Ensure this listener is a named function for proper memory cleanup.
  * **Text Rendering:** Utilize `ctx.fillText()` to draw the validated handle beneath the player avatar (Green for local, Blue for peers). Ensure the text maintains its relative position and scales correctly with the grid zoom.

* **`src/engine/RoomManager.js`**
  * Update the environment bounds from the previous 2000x2000 constraints to 1000x1000.

## Constraints & Edge Cases
* **Responsiveness:** The new UI overlays and Canvas must remain responsive and fully functional down to a 320px viewport width.
* **Rendering vs. State:** Continue to decouple the canvas rendering logic (zooming/text drawing) from the physics state updates.
* **Definition of Done:** Ensure all new functions include JSDoc comments and the `CHANGELOG.md` is updated to reflect v0.1.1 prior to finalizing the task.
