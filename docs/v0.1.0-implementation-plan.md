# Goal Description

Set up Dungeon2D: a WebRTC 2D P2P Room Engine. This will be a serverless, browser-based multiplayer template where users can create private peer-to-peer rooms via join codes and navigate a top-down 2D grid. The tech stack will include Vite, HTML5 Canvas, modern CSS, Vanilla JS, and PeerJS (for signaling).

## User Review Required

- **Artifact Persistence**: Saved as `/docs/v0.1.0-implementation-plan.md`.

## Open Questions Resolved

- **PeerJS Server**: Use the default free PeerJS cloud server.
- **Grid/Room Size**: 2000x2000 pixels. The 'room' definition will be structured in a data layer schema that can be extended later (e.g., loaded via JSON and synced with peers upon connection).
- **Visuals**: Black grid game-space. Local player is a green simple 'face' shape, peer players are blue simple 'face' shapes.

## Proposed Changes

### 1. Project Scaffolding
- Initialize a Vite project with the Vanilla JS template.
- Install `peerjs`.
- Create initial `index.html` structure with a full-viewport `<canvas>` and an absolutely positioned `#ui-layer`.
- Add `style.css` implementing a minimalist, high-contrast dark mode for the UI overlays.

### 2. Module A: UI & Signaling Controller (`src/ui/UIController.js`)
- Manage "Create/Join Room" dialogs.
- Listen for UI interactions and communicate with the network engine.
- Render connection statuses and the high-contrast join code.

### 3. Module B: WebRTC Engine (`src/network/WebRTCEngine.js`)
- Initialize PeerJS for signaling using default cloud server.
- Setup DataChannels for P2P state synchronization.
- Implement JSON payload serialization/deserialization.
- Support syncing the room data schema on initial peer connection.

### 4. Module C: Game Loop & Input (`src/game/GameLoop.js`)
- Implement a custom Event Bus (`src/utils/EventBus.js`) to decouple state from rendering.
- Capture WASD inputs and track key states.
- Run `requestAnimationFrame` loop, calculating velocity and position.
- Send positional data 20 times per second (Tick Rate logic).

### 5. Module D: Render & Physics Engine (`src/render/RenderEngine.js`, `src/game/RoomManager.js`)
- Create `RoomManager.js` to handle the data layer for the room definition (2000x2000 size, future extensible JSON structure).
- Handle dynamic canvas resizing (`window.innerWidth`/`innerHeight`).
- Implement the fixed-center camera: translate the canvas context based on player coordinates before drawing the world.
- Draw the infinite 2D grid background (black) and the rectangular room walls.
- Calculate AABB collision against room walls to restrict movement.
- Draw the local player (green face) in the center, and any connected peers (blue faces) at their relative world coordinates.

## Verification Plan

### Automated/Manual Testing
- Run `npm run dev` to start the Vite server.
- Open two browser windows to test creating a room and joining it.
- Verify that WASD moves the player, the camera stays centered, and the world moves instead.
- Verify that the player cannot pass through the defined room walls (AABB collision).
- Verify that moving in one window updates the player's position in the other window at ~20 ticks per second.
